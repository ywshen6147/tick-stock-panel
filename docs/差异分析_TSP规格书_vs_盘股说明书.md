# 我写的《TSP 产品规格书》 vs 《盘股证券交易助手 — 产品说明书（详细版 V2.0）》

> 对比对象：
> - **A（我写的）**：`tick-stock-panel/docs/产品规格书.md` —— 基于 TSP 开源项目源码实况整理
> - **B（你提供的）**：`盘股证券交易助手 — 产品说明书（详细版 09070030）.pdf`（49 页 / 13 章 / V2.0）
>
> 结论先行：**这是两个不同产品、两种不同文档体裁**。B 是"盘股"（一个更庞大的个人量化投研系统）的对外脱敏版产品说明书；A 是 TSP（tick-stock-panel，开源 A 股量化工作台）的工程规格书。二者有 ~30% 概念重叠（同为 A 股量化、多源数据、回测、监控），但**产品边界、架构复杂度、文档定位差异巨大**。

---

## 一、核心差异总览（一张表看懂）

| 维度 | A：TSP 产品规格书（我写的） | B：盘股产品说明书（你给的） |
| :--- | :--- | :--- |
| **产品本体** | tick-stock-panel 开源项目（GitHub 公开） | 「盘股」——个人本地部署的量化投研系统（未开源） |
| **文档定位** | 工程/产品规格书（PRD，含架构/接口/部署） | 对外脱敏版产品说明书（面向使用者与研究团队，**不含代码**） |
| **覆盖范围** | 以现有实现为准，如实写"有哪些功能" | 以产品愿景为准，写"系统应该怎么运转"的完整方法论 |
| **数据源** | 明确写名称：TickFlow / fuyao / stock-sdk / YAML 自定义源 | **全部脱敏**：统称"第三方行情数据 / 财经数据接口" |
| **量化阈值** | 写具体口径（连板晋级率、拥挤度分位、IC 等） | **不披露任何数值**（形态幅度、评分权重、仓位上限一律只给框架） |
| **部署形态** | Dev（3011/3018）/ Docker / 桌面 bat 启动 | 桌面应用（一键启动+托盘）+ 浏览器开发形态 + 打包安装形态 |
| **架构** | 单进程 FastAPI + APScheduler + Polars/DuckDB/Parquet | **双进程**（服务进程 + 独立流水线进程）+ 四层模型 + 双轨数据守卫 |
| **文档篇幅** | ~23KB / 11 章 / 1 个文件 | 49 页 / 13 章 + 术语表 + 4 个附录 |
| **受众** | 研发/测试（能看懂代码的人） | 使用者/研究团队（非程序员也能读） |

## 二、B 有而 A 完全没有的能力（缺口清单）

B 描述了一个**远超 TSP 现有实现的量化投研系统**，以下能力在 TSP 中不存在（或仅有雏形）：

### 1. 研究方法论层（B 第五章，TSP 完全没有）
| B 的能力 | TSP 现状 |
| :--- | :--- |
| **三大交易系统**（核心精选/强势追涨/价值回归，按行业归属路由） | ❌ 无 |
| **分层卖出体系**（6 级优先级：硬止损→势散→趋势→顶部→回撤→移动止盈） | ⚠️ 仅回测止损，无此体系 |
| **仓位/资金管理**（凯利类公式 + 阶段仓位纪律 + 账户级约束） | ⚠️ 回测有仓位参数，无账户级资金管理 |
| **组合风控与压力测试**（风险平价/风险预算/压力测试/在险价值） | ❌ 无 |
| **拥挤度分析**（板块多因子 + 时间序列百分位 + 横截面排名 + 状态机） | ⚠️ 有 RPS/概念轮动，无拥挤度状态机 |
| **透支分析**（价格相对基本面业绩"提前反映多久"） | ❌ 无 |
| **虚火诊断**（7 维虚火指数 + 三元信号 + 股权风险溢价交叉验证） | ❌ 无 |
| **股权风险溢价 / 恐慌水平（期权）** | ❌ 无 |
| **形态识别体系**（经典形态 + 强势白马形态 + 置信评分） | ⚠️ 个股分析有 9 类关键价位，无全市场形态扫描 |
| **趋势阶段生命周期**（吸筹→洗盘→主升→赶顶→下跌状态机 + 洗盘/顶部专项识别器） | ⚠️ 有市场情绪周期 6 阶段，但无个股生命周期 |
| **信号生命周期与验证**（出现→跟踪→验证→归档 + 命中率分档/标签分组统计） | ⚠️ 有监控触发记录，无信号历史验证体系 |
| **三大选股引擎**（长线/中线/短线三引擎 + 买入时机 BUY 流水线） | ⚠️ TSP 有 25 内置策略 + 因子挖掘，无"长中短三引擎"结构 |
| **全市场多因子筛选器**（自定义条件全市场挑股票） | ⚠️ TSP 有自定义信号，无全市场多因子筛选器 |
| **市场风格检测与参数自适应**（强牛/弱牛/震荡/熊 + 防守模式） | ⚠️ TSP 有 5 档 state + 情绪周期，无风格自适应参数 |
| **事件驱动研究**（事件日历/事件影响统计/催化跟踪/预期差） | ⚠️ TSP 有龙虎榜/风向标，无事件研究框架 |
| **产业链研究**（产业链—子赛道—个股三层 + 链主/龙头标记） | ❌ 无 |
| **资金主体画像**（席位画像/假机构识别/筹码集中度） | ⚠️ TSP 有龙虎榜卡片，无席位画像 |

### 2. 运维与数据治理层（B 第三、四、八章，TSP 明显更简）
| B 的能力 | TSP 现状 |
| :--- | :--- |
| **双进程模型**（服务进程只读 + 独立流水线进程写） | ⚠️ TSP 单进程 FastAPI，无独立流水线进程 |
| **双轨制数据守卫**（主写者 + 备用管道 + 影子对账 + 血缘登记） | ❌ 无（TSP 仅数据同步与实时行情互斥） |
| **四层模型**（展示/聚合服务/数据加工/数据层）+ 读写物理隔离 | ⚠️ TSP 有分层，但无物理读写隔离 |
| **新鲜度/覆盖率/血缘登记**（每模块登记"数据算到哪一天"） | ⚠️ TSP 有数据页画像，无血缘链 |
| **在线一致性备份 + 恢复演练 + 保留策略** | ❌ 无（TSP 无自动备份系统） |
| **天眼巡检**（服务/新鲜度/磁盘/选股池/回测超时/对账巡检） | ⚠️ TSP 有完整性自检，无全量巡检 |
| **告警生命周期**（产生→升级→确认→解决 + 90 天留存） | ⚠️ TSP 有监控告警，无生命周期管理 |
| **数据质量保障体系**（入库校验/口径审计/影子对账/金样例/基线差分） | ⚠️ TSP 有回测结果校验，无金样例/基线差分 |
| **报告子系统**（盘前简报/收盘简报/舆情日报/持仓风险报告，多渠道推送幂等） | ⚠️ TSP 有盘后复盘，无简报/日报体系 |
| **交易闭环**（交易计划→模拟记账→持仓分析→每日风险扫描→复盘） | ⚠️ TSP 有自选/监控，无持仓账本/模拟交易 |
| **快捷键体系**（g1-g6 页面跳转） | ❌ 无 |
| **每日 SOP / 专题研究 SOP / 风险自查清单** | ❌ 无（B 第 9.3-9.5 章） |

## 五、本质差异：为什么差这么多

1. **产品成熟度不同**
   - TSP 是**开源实现**，文档写的是"现在有什么"（如实、可验证、有代码佐证）
   - 盘股是**完整方法论系统**，文档写的是"系统应该具备的完整研究框架"（愿景级、脱敏、不展示实现细节）
2. **文档定位不同**
   - 我的 A 是**工程规格书**（PRD）：架构、接口、配置、部署，给研发/测试看
   - B 是**产品说明书**（对外）：理念、方法论、使用指引、运维 SOP，给使用者/研究团队看
3. **脱敏策略不同**
   - A 可写具体数值（档位、阈值、接口路径）
   - B 明确"不披露选股规则细节与量化阈值、不披露数据源名称、不含代码"
4. **功能边界不同**
   - TSP 明确"不对标同花顺/通达信，不做 AI 荐股"——是**选股+回测工作台**
   - 盘股是**完整投研闭环**——从数据管理→研判→选股→回测→风控→持仓→复盘→运维，覆盖面广得多

## 六、如果要把 A 升级为 B 级别的文档（建议）

如果你的目标是让我写的《TSP 产品规格书》**向《盘股产品说明书》看齐**，可以分三步：

1. **补齐方法论章节**（把 B 第五章的框架移植过来）：
   - 三大交易系统、分层卖出、仓位管理、拥挤度、透支、虚火、形态识别、个股生命周期、信号验证体系、买入时机流水线、市场风格自适应
2. **补齐运维/治理章节**：
   - 数据血缘与新鲜度登记、备份与恢复演练、天眼巡检、告警生命周期、报告子系统（简报/日报）、交易闭环（计划-记账-复盘）
3. **调整文档体裁**：
   - 从"工程规格书"改为"产品说明书"口吻：先讲理念（研究闭环/规则显式化/依据透明），再讲能力，最后讲使用 SOP
   - 增加：目标用户与场景、每日 SOP、专题研究路径、风险自查清单、术语表、常见问题

> ⚠️ 但请注意：**把 TSP 写成"盘股那样"会有风险**——B 里很多能力 TSP 并没有实现，直接写进规格书会变成"虚假宣传"（规格书与代码不符）。建议明确标注每个能力的状态：`✅ 已实现 / 🚧 部分实现 / 🎯 规划中`，或单列"愿景版"与"现状版"两栏。
